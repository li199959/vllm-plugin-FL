# Qwen3-VL-Embedding-8B PPU 适配报告（2026-11-07）

模型：`/mnt/cpfs/xiangbin/Qwen3-VL-Embedding-8B`（Qwen3VLForConditionalGeneration，last-token 池化 + L2 归一化，4096 维）
环境：T-Head PPU-ZW810E 单卡（TP1），vLLM 0.24.0 + vllm-plugin-FL 工作区 `minimax-m3-coverage-80`，pooling 服务

## 结果

| 项目 | 目标 | 结果 | 结论 |
|---|---|---|---|
| 精度（13 条样本对 HF bf16 参考） | 余弦 ≥ 0.999 量级，检索一致 | 最低余弦 0.99795，检索 8/8 | 达标 |
| 吞吐（相对参考配置） | ≥ 95% | 99.70%–99.96% | 达标 |
| FlagGems 覆盖率 | ≥ 80% | 25/26 = **96.15%**（ATen 10/11，kernel 15/15） | 达标 |

参考配置 = 同一插件只让 attention backend 走 FlagGems（`VLLM_FL_FLAGOS_WHITELIST=attention_backend`），其余为 torch / Inductor / cuBLAS。不带插件的纯 vLLM 在这台机器上起不来，和 bge-m3 一样。

| 输入长度 | 参考 tok/s | 本配置 tok/s | 比例 | E2EL 均值 参考 / 本配置 (ms) |
|---|---|---|---|---|

### 精度

样本：中/英/德/日短文本、约 1800 token 的长文本、3 张图（440×133 小图、640×336 文档页、1916×954 截图）、图文混合，共 13 条，另含 4 条检索查询。参考为 HF transformers bf16，输入格式完全按模型自带的 `scripts/qwen3_vl_embedding.py`（system 指令、`add_generation_prompt=True`、取最后一个 token、L2 归一化）。

## 启动命令

```bash
cd /mnt/cpfs/xiangbin/codex/minimax-m3-coverage-80
export CUDA_VISIBLE_DEVICES=5
export PYTHONPATH=/mnt/cpfs/xiangbin/codex/minimax-m3-coverage-80
export VLLM_DISABLE_COMPILE_CACHE=1
export VLLM_FL_FLAGOS_BLACKLIST_APPEND=scaled_dot_product_attention,_scaled_dot_product_flash_attention,_flash_attention_forward,mm,mm_out,addmm,addmm_out,linear,empty
export VLLM_FL_Q3VLEMB_STABLE=1
export VLLM_FL_Q3VLEMB_DENSE=hybrid
export VLLM_FL_Q3VLEMB_GEMS_SMALL_M=512

vllm serve /mnt/cpfs/xiangbin/Qwen3-VL-Embedding-8B --served-model-name qwen3-vl-embedding \
  --runner pooling --port 18350 --max-model-len 8192 --gpu-memory-utilization 0.85 \
  --no-enable-prefix-caching
```

脚本方式：`tools/ppu/qwen3_vl_embedding/serve_qwen3_vl_embedding.sh <run_dir> <gpu> <port> worktree`（环境变量照上设置，`EXTRA_ARGS="--no-enable-prefix-caching"`）。

**调用时必须带 `"add_special_tokens": true`**（对话格式请求还要带 `"add_generation_prompt": true`）。官方流程在末尾加 `<|endoftext|>` 并取这个 token 的向量；vLLM 的对话 embedding 请求默认 `add_special_tokens=false`，不带的话取到的是 `\n`，余弦只有 0.3–0.6。

### 环境变量

| 变量 | 作用 |
|---|---|
| `VLLM_FL_FLAGOS_BLACKLIST_APPEND` 前三项 | FlagGems flash attention 在 head_dim 72/80、序列 96–256 时输出错误或 NaN。ViT 的 head_dim 是 72，小图会命中，导致图片向量完全错误。三个入口都要禁，只禁 SDPA 两项不够，vLLM 实际走的是 `_flash_attention_forward`。 |
| `mm,mm_out,addmm,addmm_out,linear` | 8B 稠密模型以 GEMM 为主，FlagGems 在 M ≥ 1024 时比 cuBLAS 慢 12–26%，全走 FlagGems 只有参考的 46–63%。 |
| `empty` | FlagGems `empty` 每次调用有固定 CPU 开销，和 bge-m3 一致。 |
| `VLLM_FL_Q3VLEMB_STABLE=1` | last-token 池化用 `aten.index` 从 `[num_tokens, 4096]` 取行，FlagGems 把 token 数写进生成的 kernel，几乎每个 batch 都重新生成，1k 输入 p99 达 19 s。改用 `common/shape_stable.py` 的形状稳定版本。 |
| `VLLM_FL_Q3VLEMB_DENSE=hybrid` + `GEMS_SMALL_M=512` | token 数 ≤ 512 的 batch，LLM 的 4 个投影走调好 tile 的 FlagGems `linear_kernel`（这个区间和 cuBLAS 持平），更大的 batch 走 cuBLAS。这是覆盖率从 61.5% 到 96% 的来源。 |
| `VLLM_DISABLE_COMPILE_CACHE=1` | vLLM 编译缓存的 key 不看 `VLLM_FL_*`，改开关后可能沿用旧图。 |
| `--no-enable-prefix-caching` | 压测和覆盖率都要关；覆盖率脚本三轮用同一 seed，开着前缀缓存时 profile 轮命中 49–66%，统计不可信。 |

## 覆盖率明细

未覆盖只有 `aten.mm`：token 数 > 512 的 batch 走 cuBLAS。要覆盖它，大 batch 也得走 FlagGems，吞吐会掉到参考的约 80%。

## 发现的问题

1. **FlagGems flash attention 在 head_dim 72/80 下结果错误**（序列 96–256 时乱码或 NaN；d64/d128 和长序列正常）。可单独复现，应提给 FlagGems。Qwen3-VL-30B-A3B 的 ViT 也是 head_dim 72，之前 ERQA 上没查清的 `!` 乱码可能是同一个原因。
2. **embedding 请求的 EOS**：见上面“调用时必须带 `add_special_tokens`”。
3. **FlagGems GEMM 大 M 慢于 cuBLAS 12–26%**，见 `tools/ppu/qwen3_vl_embedding/sweep_linear.py`。
