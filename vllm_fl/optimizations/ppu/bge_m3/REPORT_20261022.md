bge-m3 性能、覆盖率与精度测试报告（2026-10-22，v9）
=================================================

取代 `REPORT_20261021.md`（v7）。v7 的对比基线是“只有 attention 走 Gems 的插件配置”，它本身用的是 Triton attention，比原生 vLLM 慢一倍以上；以用户提供的原生 vLLM 结果为基线后，v7 不达标，v9 改用 PPU FA3 attention 后达标。

1. 配置与命令
-------------

```bash
cd /mnt/cpfs/xiangbin/codex/minimax-m3-coverage-80
export PYTHONPATH=$PWD
export VLLM_DISABLE_COMPILE_CACHE=1
export VLLM_FL_FLAGOS_BLACKLIST_APPEND=broadcast_to,mm,mm_out,addmm,addmm_out,linear,empty
export VLLM_FL_BGEM3_STABLE=1             # 运行期尺寸的 Gems index / copy_
export VLLM_FL_BGEM3_DENSE=hybrid         # ≤4096 token 的 batch（CUDA graph 尺寸）linear 走 Gems
export VLLM_FL_BGEM3_GEMS_LINEARS=
export VLLM_FL_BGEM3_GEMS_SMALL_M=4096
export VLLM_FL_BGEM3_ATTN=fa3             # encoder attention 走 PPU FA3
export VLLM_FL_BGEM3_FA3_MIN_TOKENS=2048  # <2048 token 的 batch 仍走 Triton
CUDA_VISIBLE_DEVICES=8 vllm serve /mnt/cpfs/xiangbin/codex/bge-m3 \
  --served-model-name BAAI/bge-m3 --runner pooling --port 8006 \
  --max-model-len 8192 --gpu-memory-utilization 0.85 \
  --compilation-config '{"max_cudagraph_capture_size":4096}' --no-enable-prefix-caching
```

压测为用户给的 EvalScope 命令（`random_embedding`，64 并发，256 请求，warmup 10，长度 1024 / 2048 / 4096 / 8190），连跑两轮。两轮 `Cached Prompt tok/s` 均为 0。

3. 原因与改动
-------------

vLLM 对 bge-m3 这类 ENCODER_ONLY 模型的 attention 走 `triton_prefill_attention.context_attention_fwd`。在 PPU 上它比 FA3 varlen 慢 3.2–3.4 倍（16 头 × 64，fp16，非 causal）：

| batch | Triton | FA3 |
|---|---:|---:|
| 8 × 1026 | 1.74 ms | 0.54 ms |
| 2 × 4098 | 5.52 ms | 1.73 ms |
| 1 × 8192 | 10.31 ms | 3.12 ms |

长输入时 attention 是 GPU 时间的大头，这就是 v7 越长越慢的原因。`VLLM_FL_BGEM3_ATTN=fa3`（`attention.py`）把 `TritonAttentionImpl._forward_encoder_attention` 换成 `torch.ops.flash_attn_3.fwd`，输出与 Triton 一致（单测最大误差 0）。

为了覆盖率保留两处 Gems/Triton：

- FA3 在 batch 少于 2048 token 时改用另一个 tile 变体（64×128），多一个未覆盖 kernel。这些是尾 batch，`FA3_MIN_TOKENS=2048` 让它们继续走 Triton（单次多 13–150 µs）。
- CUDA graph 回放里的 cuBLAS kernel 关联不到 ATen，会成为独立未覆盖项。`GEMS_SMALL_M` 从 512 提到 4096（等于 graph 捕获上限），所有 graph 尺寸的 linear 都走 Gems；更大的 eager batch 仍走 cuBLAS。

只加 FA3、不做这两处时覆盖率是 15/20（75%）。

4. 覆盖率
---------

vllm-gpu-coverage skill 口径，profile 轮为 1024 输入、64 并发、1024 请求（两轮预热 + 一轮 profile），`verification.json` 的 `checks_passed=true`。报告：`profiles/bge_m3_v9_cov_20261022/gpu_coverage/`。

| | 覆盖 | 合计 |
|---|---:|---:|
| GPU 关联 ATen | 11 | 12 |
| 独立 GPU kernel | 5 | 6 |
| **合计** | **16** | **18（88.89%）** |

未覆盖：`aten.addmm`（大 batch 的 cuBLAS GEMM）和 FA3 的 `FlashAttnFwdSm80` kernel。
